# Code-point parser, decode outside

The stream parser consumes **Unicode code points, not raw bytes**; an incremental UTF-8 decoder (`codecs.getincrementaldecoder`) sits in front and resolves byte-level ambiguity before the state machine ever sees input. This keeps the parser's input alphabet uniform and lets the state table match xterm.js's VT500 parser exactly — including the 8-bit C1 entries (U+009B → `CSI_ENTRY`, U+009D → OSC, U+0090 → DCS…), which are free at the code-point level. A **raw-byte 8-bit decode mode** (the DECSCL world, bytes 0x80–0x9F as controls) is deliberately omitted: it is mutually exclusive with UTF-8 (the C1 range overlaps the continuation-byte range 0x80–0xBF), no modern program emits it, and a lone 0x80–0x9F byte degrades gracefully to U+FFFD. Reversal cost: any change to the input unit touches every transition edge.
